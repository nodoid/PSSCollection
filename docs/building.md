# Building and shipping

## What you need

* The .NET SDK that can target `net10.0` and `net11.0` (the heads use both), plus the workloads:
  `dotnet workload install ios android maccatalyst` as needed.
* MonoGame 3.8.6.1 arrives through NuGet (`MonoGameVersion` in `Directory.Build.props`); the
  DesktopGL build also needs SDL2 and OpenAL, which come with the MonoGame packages.
* **iOS / macOS:** Xcode, plus an Apple Developer account and the certificates and profiles below.
* **Android:** the Android SDK with API 32 or later, and a JDK.
* **Windows MSIX:** a Windows machine or VM with the Windows SDK — `tools/build_windows.ps1` restores
  `Microsoft.Windows.SDK.BuildTools` for `makeappx` and `signtool`. MSIX cannot be assembled on macOS.

Version and store build number live in one place, `Directory.Build.props`
(`<Version>1.0.0</Version>`, `<BuildNumber>1</BuildNumber>`). Bump the build number for every store
upload; both the App Store and Partner Center reject a repeat.

## Building each head

```bash
dotnet build PSSCollection.slnx            # libraries and heads
dotnet test PSSCollection.Tests            # engine tests (xunit v3, Microsoft.Testing.Platform)

# macOS (and Linux/Windows GL)
tools/build_macos.sh                       # dotnet publish -> build/macos/osx-arm64, then
                                           # build/macos/PSS Collection.app with Info.plist + icns

# iOS (device)
dotnet build PSSCollection.iOS -c Release -f net11.0-ios -p:RuntimeIdentifier=ios-arm64

# iOS (simulator, for screenshots)
dotnet build PSSCollection.iOS -c Debug -f net11.0-ios \
    -p:RuntimeIdentifier=iossimulator-arm64 -p:CodesignKey= -p:CodesignProvision=

# Android
dotnet build PSSCollection.Android -c Release -f net10.0-android

# Windows
dotnet publish PSSCollection.WindowsDX -c Release -r win-x64 --self-contained true \
    -p:EnableWindowsTargeting=true -o build/windows
```

`build/` is publish output and is ignored by git; only `tools/` and the source are tracked.

## The release pipeline

`tools/build_release.sh [macos] [ios] [android] [windows]` builds the selected targets into
`Releases/<version>/` and writes `SHA256SUMS.txt`. With no arguments it builds everything.

| File | Built by | Notes |
|------|----------|-------|
| `PSS-Collection-1.0.0-macOS.pkg` | `build_macos` in the script | Mac App Store flat installer |
| `PSS-Collection-1.0.0.ipa` | `build_ios` | App Store archive, `rel-pss` profile |
| `PSS-Collection-1.0.0.aab` | `build_android` | Play upload, signed with the upload key |
| `PSS-Collection-1.0.0.apk` | `build_android` | Sideloading, same key |
| `PSS-Collection-1.0.0-win-x64.msix`, `-win-arm64.msix` | `build_windows.sh` | Packed inside the Windows VM |

Neither `Releases/` nor `Stores/` is committed.

### macOS specifics

The bundle is signed for the Mac App Store, which has more rules than a notarised download:

* **Profile.** `rel-pss-mac.provisionprofile` must be in `~/Downloads`. It is copied to
  `Contents/embedded.provisionprofile`, and the entitlements file for the signing is generated by
  merging the profile's `com.apple.application-identifier` and `com.apple.developer.team-identifier`
  into `PSSCollection.DesktopGL/macOS.entitlements` (sandbox + JIT).
* **Quarantine.** Anything downloaded carries `com.apple.quarantine`, and validation rejects a
  package containing a single quarantined file (ITMS-91109). The script runs `xattr -cr` over the
  bundle after embedding the profile, then re-checks the expanded package payload before finishing.
* **Re-signing with `--deep`.** The .NET runtime ships as PE assemblies. `codesign` signs those with
  a *detached* signature held in the file's extended attributes, which the xattr cleanup also wipes,
  so signing is one `--deep` pass that re-signs every nested object, followed by a bundle-only pass
  that applies the entitlements to the app rather than to the files inside it.
* **Minimum OS.** Transporter reads the minimum system version from the archive's *product
  definition*. The script therefore builds with `productbuild --product product_definition.plist
  --component "PSS Collection.app" /Applications`, where the definition declares `os 26.0` to match
  `LSMinimumSystemVersion`. Declaring it in a `--distribution` file instead is reported back as
  "none" (error 90264).
* **arm64 only.** A .NET publish carries an architecture-specific `System.Private.CoreLib.dll`, so
  an arm64 and an x64 publish cannot be lipo-merged into one universal bundle — the arm64 apphost
  refuses the x64 CoreLib with `0x8007000B`. Ship one architecture per package or publish RID-neutral
  assemblies.
* `createdump` is deleted from the bundle: it cannot be sandboxed or signed for the store.

### iOS and Android specifics

* iOS needs `rel-pss.mobileprovision` in `~/Library/MobileDevice/Provisioning Profiles/` for a
  Release archive; the script copies it from `~/Downloads` if it is missing.
* Android signing uses `~/keys/pss-upload.jks` (alias `pss`) and `~/keys/pss-upload.properties`,
  which holds `storePassword=`. The script passes it through `PSS_KEYSTORE_PASS`; the key material
  never enters the repository and both files are matched by `.gitignore`.
* The debug-only `ShotDriver` in `PSSCollection.iOS/Program.cs` drives scripted taps on a simulator
  for screenshots, gated behind the `PSSC_SHOT` environment variable. It compiles out of Release.

### Windows specifics

`tools/build_windows.sh` runs `tools/build_windows.ps1` inside the Parallels VM, because `makeappx`
and `signtool` only exist there. `prlctl exec` runs as SYSTEM with no desktop, so anything that needs
a window — including the screenshot capture — goes through a scheduled task in the logged-in session
(`tools/capture_windows.bat`).

## Store material

```bash
python3 tools/make_store_artwork.py        # icons, artwork, framed screenshots -> Stores/
python3 tools/make_branding.py             # the shared pixel-font drawing helpers
python3 tools/make_icons.py                # app icons from art/icon-1024.png
```

`tools/make_store_artwork.py` copies the raw device captures from `Stores/ios`,
`Stores/android/screenshots`, `Stores/windows/shots` and `/tmp/mac-shots`, frames the desktop ones,
and writes `submission.md` alongside. The captures themselves come from driving the real app:

| Platform | Driver | Sizes produced |
|----------|--------|----------------|
| iPhone | `PSSC_SHOT` + simulator on a 6.3" device | 2622x1206 (the App Store's required iPhone slot) |
| iPad | same driver on a 13" device, rotated | 2752x2064 |
| Android | `adb shell input tap` on a 1080p emulator | 1920x1080 |
| macOS | `tools/capture.sh` with `cliclick` | 1280x720, framed to 2880x1800 |
| Windows | `tools/capture_windows.ps1` in the VM | 1280x720 client, framed to 1920x1080 |

Apple requires one iPhone set at the *medium Dynamic Island* size (1206x2622 or 1179x2556,
landscape for these games) and, for iPad apps, one 13" set (2064x2752 or 2048x2732). Other sizes —
including the 6.9" class — are optional and scale down from the required set.
